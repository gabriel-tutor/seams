# Checkout

Always in this session, one PR at a time, even in a batch: fetches and worktree creation in one repository race on git's lock files when run in parallel.

1. **The repository.** The current directory's repository when one of its remotes points at `owner/repo`; otherwise a clone made for this review: `gh repo clone owner/repo "${TMPDIR:-/tmp}/seams-pr-review/clones/owner-repo" -- --filter=blob:none`, then write a `.seams-pr-review` marker into it. A clone is reused only when it holds that marker.
2. **Fetch and pin.** `git -C <repo> fetch --no-tags <remote> pull/<n>/head` (works for forks), then `git -C <repo> rev-parse FETCH_HEAD` must equal `headRefOid`; if it differs, the pull request moved: fetch again and re-pin, and say so. Then `git -C <repo> fetch --no-tags <remote> <baseRefName>` and the baseline is `git -C <repo> merge-base <headRefOid> FETCH_HEAD`, the commit GitHub diffs the pull request against.
3. **The evidence directories.** Once every pull request is pinned, one call for them all: `python3 <skill-dir>/scripts/evidence.py pin --pr <url> <headRefOid> <baseline> --pr ...`, with each pull request's `url` from the Gate, and `--afresh` first when the request says `afresh`. It names each `$EVID`, `${TMPDIR:-/tmp}/seams-pr-review/<owner>-<repo>-<n>-<first 7 of the head>`, the same way on every run, and writes its `.seams-pr-review` marker (the pull request's URL, the candidate and baseline SHAs, the time). The marker is what makes the directory and its worktrees this review's own; a directory name alone is not proof. Then it says, for each pull request, where its review starts, from what an earlier run left there:
   - **new**, or **afresh**: every step runs. Afresh, the request said `afresh`, or the earlier run was pinned at another head or baseline, or wrote an older marker; its earlier outputs are removed, so a stale review can never stand in for this one.
   - **continue with its checks**: its checks ran at this head and baseline, so `checks/` is kept and the checks in `checks.json` do not run again (a check the list has that `checks.json` lacks runs with `--merge`). Every other step runs: Understand, Try it and Security, Review and Draft, since they leave nothing a later run could keep.
   - **continue at Draft**: its `review.json` is kept; build its payload (`draft-and-post.md`).
   - **reuse**: its review is drafted at this head and baseline and goes to Post; a review already posted there has nothing left to post.

   A head that moved has a directory of its own and starts new: old evidence never stands in for it. When a directory exists without the marker, is a link, is another user's, or holds another pull request's evidence, it exits 1 with nothing pinned: stop and ask. With more than one pull request it also writes the batch's progress file (`batch.md`).
4. **Record the user's state, once, before the first pull request's checkout.** First remove the worktrees `evidence.py` says to remove, as `cleanup.md` says. Then `git -C <repo> status --porcelain` and `git -C <repo> worktree list --porcelain`, into `${TMPDIR:-/tmp}/seams-pr-review/before-<repo name>.txt`, leaving out the lines of this review's own worktrees that it keeps. Cleanup compares against this one record after the last pull request's worktrees are gone, so a batch's own worktrees never read as a change.
5. **The worktrees and the diff,** only those `evidence.py` says to make: `git -C <repo> -c core.hooksPath=/dev/null worktree add --detach "$EVID/head" <headRefOid>` and `git -C <repo> -c core.hooksPath=/dev/null worktree add --detach "$EVID/base" <baseline>` (no git hook runs: a checkout-time hook runs inside the new tree and reads its files, so the pull request would choose its command), then `git -C <repo> diff <baseline> <headRefOid> > "$EVID/pr.diff"`: exactly the diff GitHub shows. A diff that failed is made again before anything reads it.

# Changelog

## 3.0.1 — 2026-09-18

- The gate's ledger directory is per user: `$TMPDIR/seams-<uid>/`, the tmux convention. In 3.0.0 one `seams/` directory served every user of a shared Linux `/tmp`; it belonged to whoever's session came first, the next user's `chmod` raised `EPERM`, and because the hooks fail open their gate was silently off. macOS was never affected (its `$TMPDIR` is per user). A session running across the upgrade loses its ledger once; one declaration restores it.
- A `LICENSE` at the repository root, the same MIT text as `plugin/LICENSE`, so GitHub shows the license.
- `docs/compatibility.md` records the 2026-09-18 checks: Claude Code 2.1.276; a fresh install from GitHub into an empty config directory, its cached hooks driven with Claude Code's event shapes and two headless sessions on that copy; Matt Pocock's upstream skills still at the recorded hashes.

## 3.0.0 — 2026-09-16

The workflow is enforced by hooks, carried past the merge, and measured by a harness that reports what happened. Grouped by the findings of the 2026-09-15 review (F01–F09), after the one change that is not a finding. The plugin id `matt-pocock-workflow` and the marketplace name `my-workflow-agent-skills` are unchanged: `claude plugin update matt-pocock-workflow@my-workflow-agent-skills` is the whole upgrade. Evidence for each claim is in `docs/plugin-behavior-tests.md` and `docs/compatibility.md`.

**The gate and the done-check (ADR-0001).** A PreToolUse hook refuses any change to the project (`Edit`, `Write`, `MultiEdit`, `NotebookEdit` to a path outside the temp and Claude config directories, or a shell command its classifier labels a mutation) until a process skill has been invoked for the current request, with a reason that names the label and the routes; a Stop hook refuses to end a turn once when non-documentation files changed and `matt-pocock-workflow:verification-before-completion` did not follow. The ledger is one JSON file per session under the temp directory, holding skill names, tool names and paths only; `startup` and `clear` reset it, `compact` and `resume` keep it; a short go-ahead ("yes", "continue", an option letter) keeps the declaration, any other prompt starts a new request; a slash command the user types is a declaration; Superpowers' process skills are not. Every hook fails open and runs on Python 3.9 (macOS's system interpreter crashed the 2.1 hook on import and, failing open, left the session without a bootstrap). New `trivial` skill: the cheap declaration, carrying the test of what is not trivial.

**F01, a review that sees the candidate.** `implement` commits the ticket's files by name before `code-review` (unrelated dirty or untracked files are listed as excluded, never staged), passes the merge-base as the fixed point with HEAD as the candidate, reports an empty diff instead of reviewing it, commits review fixes and re-runs the checks they affect, and names the candidate SHA in the definition-of-done table. `routing.md`: evidence belongs to a candidate; an unchanged candidate's suite is reused, a change makes a new candidate.

**F02, Seams-owned flow skills (ADR-0002).** `to-spec`, `to-tickets` and `implement` are Seams' own adaptations of Matt Pocock's (MIT, attributed with the upstream commit and file hashes in `plugin/THIRD_PARTY_NOTICES.md`), so nothing follows a user-only skill by reading its file; each keeps its gate before starting and before publishing. `scripts/tests/test_plugin.sh` warns, without failing, when an installed upstream file differs from the recorded hash.

**F03, session-start knows what is installed.** The hook resolves the config directory from `CLAUDE_CONFIG_DIR`, else `~/.claude` (paths with spaces and symlinked skill directories included), checks all nine Matt Pocock skills the plugin invokes, and names the missing ones with the one install command (`npx skills add mattpocock/skills -g -a claude-code`). `docs/compatibility.md` records the tested skills commit and each file's SHA-256.

**F04, an installer that tells the truth.** `scripts/install.sh` checks the `claude` CLI, Node and `python3` at 3.9 or newer (naming the version found when too old), installs Matt Pocock's skills only through a terminal (piped without one it prints the command instead), and runs every `claude plugin` command through one helper that stops at the first failure with that command's output. It writes no `settings.json` and takes no backup; the marketplace and the enabled plugin are recorded by the `claude plugin` commands themselves. `test_install.sh` runs it in fixture homes against a stub `claude`: settings byte-identical, a failing step stops it, a second run changes nothing, a home without the skills and no tty exits with a message.

**F05, a harness that measures what it claims.** `scripts/behavior_test.py` imports the gate's classifier (`plugin/hooks/seams_gate.py`), so a shell write before the first Skill call scores as straight-to-code; a verdict is confirmed by its own result; gate refusals, failed calls, the platform's permission denials, timeouts, exit codes and the candidate are recorded; `--assert` judges every run against `tests/scenarios/<name>/expect.json` and exits 1 when any is short, infrastructure errors listed apart from misses; `judge` re-judges saved records and `report` prints the counts table `docs/plugin-behavior-tests.md` carries. Four gate scenarios (a pressured one-line change, a shell write, a typo, "commit this") join the six routing scenarios. The docs describe the harness as a routing probe, not an outcome evaluator, and the question-mark count as a formatting heuristic.

**F06, routing by risk, authorization preserved.** The bootstrap's table routes by size and by risk: `trivial`* for trivial changes, a Sensitive row at any size (auth, permissions, secrets, billing, migrations, infrastructure, CI or deploy config, a public API, anything destructive: `grill` on the security and failure axes, `code-review` required), `incident`* for a live outage, `release`* for shipping, a new app's ticket 01 as the walking skeleton. Rule 4: a yes covering later steps is not asked again; deploy and publish always ask. The grill skips a decision the code or an earlier answer already settles. The bootstrap fits 2,900 bytes at a cache-length plugin path; the Superpowers-overlap sentence and the support-skill owners moved to `routing.md`.

**F07, past the merge.** New `release` skill: a readiness table (integrated candidate, suite green on that SHA, artifact built and identified, config per environment, migration and rehearsed restore when data changes shape, abort conditions and rollback path, the applicable checks, the smoke plan; anything unmet blocks), a deploy only after an explicit yes naming target, environment and candidate (staged environment first when one exists), verification that the running version is the candidate with the abort path on failure, an operations handover, and a target table for web hosts, containers and VPSs, mobile stores, CLI and library registries, browser extension stores and desktop. New `incident` skill: impact, contain (every outward action behind a yes), restore and confirm, then `diagnosing-bugs`, the fix through the normal route with a regression test first, a post-mortem note under `docs/incidents/`. `foundations` surveys deploy target and pipeline, environments and config, backups and restore, monitoring and alerts, dependency and secret scanning. `to-spec` adds a Release subsection when the work ships; `to-tickets` ends with a release ticket then. Every handover names the stage reached: designed, built, integrated, release-ready, deployed, operated.

**F08, executable acceptance for security, product quality and operations.** `to-tickets` turns the negative cases the design lens raised into acceptance criteria; `release` runs the applicable checks (dependency audit, secret scan, accessibility for a UI, load when the lens flagged scale) before a deploy; the Sensitive row makes the review required whatever the size.

**F09, bounded process cost.** The 150k-token continuation figure is gone; `routing.md` carries a judgment rule for phase boundaries, names the durable state (spec, tickets, `CONTEXT.md`, ADRs; a resumed ticket reads them and never relies on chat memory), and reuses evidence for an unchanged candidate. The bootstrap stays small and loads the release and incident detail only when those skills run.

**Tests and CI.** The gate module's unit tests, the hook suite fed JSON on stdin (under the default `python3` and the system 3.9), the session-start suite, the installer suite, the static plugin checks (`claude plugin validate --strict`, headings, wording, checksums, one version across both manifests, the README badge and this file), the harness's own tests and the sandbox-workspace suite run through `scripts/test.sh`, and on macOS and Ubuntu in `.github/workflows/test.yml` on every push to `main` and on pull requests. Windows is not supported.
